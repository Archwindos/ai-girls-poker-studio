# 运行与维护

## 启动

Windows 双击项目根目录的 `启动选图.cmd`。启动器会寻找可用 Python、检查依赖并打开当前版本的本地服务。若旧版占用端口，会选择空闲端口；不会关闭其他进程。请以启动器打开的地址为准，不固定收藏 8765。

首次使用需要 Python 3.10 或更新版本。在项目根目录打开终端执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r 04-制作工具\requirements.txt
```

随后双击 `启动选图.cmd`。图像渲染使用 Python 包 `pypdfium2`；字体与 ICC 随工具携带，不需要另装 Poppler，也不要求存在 Codex 的本机缓存。

其他系统安装同一依赖后，可执行：

```text
python 04-制作工具/webui/serve_review.py --port 8765
```

本轮实际验收环境为 Windows；其他系统的使用入口未作实机验收。

## 数据归属

- `02-创作资产/asset-registry.json` 是素材登记表。相对路径指向同一素材库，包含角色、预览、逐图布局、牌背、盒面和名称资产。
- `05-制作记录/当前状态/selections.json` 保存当前选择与完整历史。
- `05-制作记录/当前状态/deck-config.json` 保存黑红槽位、包装选择、尺寸和版本。
- `01-发布成品/当前选择` 按选择版本保存选中原画，历史输出保留。
- `01-发布成品/导出批次` 保存冻结批次。失败任务不覆盖成功任务。

旧 WebUI 目录中的选择文件只作为迁移来源；新工具启动时仅在新状态不存在时复制。以后以 `05-制作记录/当前状态` 为准。新版页面要求当前服务版本凭据；过期页面会拒绝写入，避免多版本互相覆盖。

## 新增原画与排版

在 WebUI 点击“添加候选”，选择角色、牌背或盒面，提供新的稳定编号和图片。编号不可覆盖已有资产。导入角色不会自动勾选，也不会替换槽位。

角色原画应不含牌点、花色和模型名。导入后点击大图中的“设置排版框”：左上、右下角标与模型名分别放在留白区。框的位置按原画百分比保存。网页可拖动与缩放，底部文字的旋转方向保存在布局中。

缺少布局的素材会明确阻止导出。框放进图内并不等于印刷安全，最终导出仍检查 R4 圆角与偏切余量。已有加字预览不可直接冒充无字原画。

高级用户可用命令行导入：

```text
python 04-制作工具/production/import_candidate.py --source 03-原始素材/new.png --id GPT-05 --role gpt --name 新礼服 --layout 03-原始素材/new-layout.json
```

布局示例见 `layout-example.json`。坐标是 `[左, 上, 右, 下]`，范围 0～1。新牌背默认用边缘背景检测保护区，检测失败时需重新准备有足够边缘余量的面稿；不会默默裁掉装饰。

## 生产规则

角色选择和生产槽位是两件事：可收藏多张，但每位角色只指定一张黑色图和一张红色图。恢复历史选择后需重新检查槽位，缺项不会自动找别图代替。

当前商家印刷配置默认每边 2 mm、R4、偏切假设 ±1 mm、角标/名称安全距离至少 5 mm。排版根据实际可见花框居中，而不是按源画布的空白边居中。正面等比缩放；长宽比不同时，四边留白不必相等，但上下和左右应各自平衡。

导出前冻结原画和名称图字节与哈希。内置临时 PDF 仅用于矢量文字栅格化，不交给商家。输出 61 张 RGB PNG 与 61 张嵌 ICC 的 CMYK JPG，商家 ZIP 只收 JPG 和简短说明。牌盒仍是六个独立面稿，不能当作已完成的厂商刀模。

## 发行与备份

```text
python 04-制作工具/build_release.py
```

发行脚本只收运行所需代码、全部创作资产、原始参考、来源资料及当前状态；不收旧输出、缓存、日志、服务 PID 或环境密钥。输出目录为 `01-发布成品/工具发行`，每次新建独立发行目录和 ZIP。

完整备份可以保留整个工作区。轻量移机和发布使用工具发行 ZIP 即可，不需要隐藏兼容链接。历史重建脚本和旧输出仍留在本地归档，不作为新版启动依赖。
